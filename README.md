## :dart: O guia para alavancar a sua carreira

> Cypress é o framework de testes end-to-end e de componentes mais usado hoje para aplicações web em JavaScript/TypeScript: em vez de controlar o navegador de fora (como o Selenium via WebDriver), ele roda dentro do próprio navegador, junto com a sua aplicação, o que torna os testes mais rápidos, mais estáveis e muito mais fáceis de depurar. O ecossistema inclui o Cypress App (gratuito e open source), o Cypress Cloud (dashboards, paralelização e depuração de falhas em CI) e o Cypress Studio (gravação de testes point-and-click). Este guia reúne documentação, cursos, ferramentas e comunidades para quem quer sair do zero em automação de testes até quem já escreve testes e quer usar Cypress Cloud, testes de componente e os recursos de IA no dia a dia. Recursos em português e gratuitos vêm primeiro em cada seção, e todo link foi verificado.

## 🗺️ Roadmap

Cypress não tem um roadmap linear próprio — ele é uma peça dentro do caminho maior de quem quer trabalhar com testes automatizados de front-end (QA/SDET). Use estas referências para se situar:

- [roadmap.sh — QA Roadmap](https://roadmap.sh/qa) — Roteiro visual e interativo mantido pela comunidade para quem quer virar analista/engenheiro de QA, com automação de testes (Cypress incluso) como uma das trilhas.
- [Por que Cypress? (documentação oficial)](https://docs.cypress.io/app/get-started/why-cypress) — Explica oficialmente o que o Cypress resolve e quando ele é a ferramenta certa, antes de você investir tempo aprendendo.
- [Tipos de teste com Cypress (documentação oficial)](https://docs.cypress.io/app/core-concepts/testing-types) — Diferença oficial entre teste end-to-end e teste de componente, os dois pilares do Cypress.

**Trilha resumida** (siga na ordem; cada etapa tem recursos nas seções abaixo):

1. **Base de JavaScript** — Cypress é 100% JavaScript/TypeScript; domine fundamentos da linguagem antes de começar.
2. **Instalação e primeiro teste** — instale via npm, abra o Cypress App e escreva seu primeiro teste `.cy.js`.
3. **Seletores e comandos** — `cy.get()`, `cy.visit()`, `cy.click()`, `cy.type()`, encadeamento de comandos e a fila assíncrona do Cypress.
4. **Assertivas e boas práticas** — `should`, `expect`, seletores resilientes (`data-cy`) e por que evitar `cy.wait()` com tempo fixo.
5. **Fixtures, intercepts e mocks de API** — `cy.intercept()` para controlar chamadas de rede nos testes.
6. **Testes de componente** — testar componentes React/Vue/Angular isolados, sem subir a aplicação inteira.
7. **CI/CD e Cypress Cloud** — rodar testes em pipeline, paralelizar execuções e usar o dashboard para depurar falhas.
8. **Cypress Studio e gravação de testes** — gerar testes automaticamente interagindo com a aplicação.

**Por onde começar:**

1. **Instale o [Node.js](https://nodejs.org/)** (LTS) — pré-requisito para instalar o Cypress via npm.
2. **Leia [Por que Cypress?](https://docs.cypress.io/app/get-started/why-cypress)** e a página [Como o Cypress funciona](https://www.cypress.io/how-it-works), ambas oficiais, para entender a arquitetura antes de instalar.
3. **Faça o tutorial interativo em [learn.cypress.io](https://learn.cypress.io/)**, oficial e gratuito, direto no navegador — não precisa instalar nada.
4. **Siga o guia oficial [Escrevendo seu primeiro teste E2E](https://docs.cypress.io/app/end-to-end-testing/writing-your-first-end-to-end-test)** e rode seu primeiro `npx cypress open`.
5. **Estude as [boas práticas oficiais](https://docs.cypress.io/app/core-concepts/best-practices)** desde o início — evita reescrever testes ruins depois.
6. **Pratique em um app de exemplo real:** clone o [Cypress Real World App](https://github.com/cypress-io/cypress-realworld-app), a aplicação de referência oficial usada para ensinar boas práticas.
7. **Aprenda a mockar chamadas de rede** com `cy.intercept()` e a testar componentes isolados com [Component Testing](https://docs.cypress.io/app/component-testing/get-started).
8. **Configure CI e explore o [Cypress Cloud](https://docs.cypress.io/cloud/get-started/introduction)** para rodar testes em paralelo e depurar falhas com contexto completo.

Seu primeiro teste em poucos minutos:

```bash
npm init -y
npm install cypress --save-dev
npx cypress open        # abre o Cypress App e cria a estrutura de pastas
```

```js
// cypress/e2e/primeiro-teste.cy.js
describe('Meu primeiro teste', () => {
  it('visita o Guia Dev Brasil e verifica o título', () => {
    cy.visit('https://github.com/arthurspk/guiadevbrasil')
    cy.get('h1, strong').should('exist')
  })
})
```

```bash
npx cypress run          # roda os testes em modo headless, direto no terminal
```

## 🤖 IA na prática

O Cypress passou a embutir recursos de IA como parte oficial do produto (App e Cloud), não como plugin de terceiros — vale conhecer antes de sair colando prompts genéricos.

**Recursos de IA nativos do Cypress**
- `cy.prompt` — comando oficial que gera testes "self-healing" a partir de uma descrição em linguagem natural do que deve ser testado.
- **Studio AI** — dentro do [Cypress Studio](https://docs.cypress.io/app/guides/cypress-studio), sugere automaticamente quais assertivas fazem sentido para o elemento que você acabou de interagir (visibilidade, texto, valores de formulário, URL).
- **Cloud MCP e Cloud CLI** — no [Cypress Cloud](https://www.cypress.io/cloud), analisam falhas de teste (logs de console, atividade de rede, snapshots do DOM) e geram um resumo do porquê o teste quebrou.
- Veja o resumo oficial em [cypress.io/ai](https://www.cypress.io/ai).

**Para aprender**
- Peça para uma IA **explicar por que um teste é "flaky"** colando o próprio código do teste — geralmente aponta para seletor frágil ou espera implícita mal feita.
- Peça **exercícios com gabarito**: "me dê um HTML simples de formulário e um teste Cypress incompleto; eu escrevo os `cy.get()` que faltam".
- Peça para **comparar duas abordagens** (ex.: `cy.intercept()` vs. esperar por um elemento na tela) e explicar o trade-off.

**Para trabalhar**
- Use o [GitHub Copilot](https://docs.github.com/pt/copilot) ([visão geral](https://github.com/features/copilot)), o [Cursor](https://cursor.com/) ou o [Claude Code](https://code.claude.com/docs/en/overview) para gerar o esqueleto de um teste a partir de uma user story, depois revise seletor por seletor.
- Depois de qualquer sugestão aceita, rode a suíte localmente (`npx cypress run`) — teste que "parece certo" mas nunca rodou é dívida técnica.
- Peça para a IA sugerir **seletores `data-cy`** a partir do JSX/HTML do componente, em vez de usar classes CSS, que quebram com qualquer mudança de estilo.

**Limites e boas práticas**
- IAs generalistas confundem sintaxe do Cypress com a do Playwright ou do Selenium — sempre confira contra a [documentação oficial](https://docs.cypress.io/api/table-of-contents).
- Elas tendem a sugerir `cy.wait(5000)` (espera fixa) para resolver flakiness — isso é o oposto de uma boa prática; peça explicitamente por `cy.intercept()` ou asserções que esperam a condição certa.
- Não cole seletores, dados de usuários reais ou segredos de ambiente de teste em ferramentas sem a política da sua empresa.
- O `cy.prompt` e os recursos do Cloud MCP são recentes (2026) e ainda evoluindo rápido — sempre confira o [changelog oficial](https://docs.cypress.io/app/references/changelog) antes de assumir que um recurso descrito em um tutorial antigo ainda funciona igual.
